# Account Default Cover And Intro Style

日期：2026-03-29

## 这份说明在定什么

给当前账号定两条默认规则：

1. 以后 `图 1` 默认固定为 `生图封面`
2. 以后“完整介绍型”帖子，默认写成让小白 `3 段内跟上` 的风格

## 一、图 1 默认生图

从现在开始，这个账号默认：

- 图 1 = 生图封面
- 图 2-图 4 = 真实图 / 官方截图 / 生图混编

为什么：

- 信息流里先要一个稳定封面系统
- 真实截图更适合做证据页，而不是每次都拿来争首停
- 如果每篇都重问“图 1 要不要生图”，封面系统永远锁不住

例外：

- 用户明确说这次首图不用生图
- 或这题本质上必须靠证据截图成立

## 二、当前账号默认封面结构

参考样本：

- `2026-03-28 🏀 WNBA 好日子来了？克拉克薪水暴涨7倍`（这是单点案例，不是 scope 上限）

> **scope 注意**：早期版本把 Clark 那篇逆向成「写实真人 + 球馆深色底」默认。
> 2026-04-26 视觉宪法重写后，账号默认改成**漫画化人物 + 漫画化背景**。
> Clark 案例的封面骨架（三层结构 / 字体 / 标题规则）保留，写实风格部分作废。

封面三层结构，从上到下：

### 1. 标题区（最多两行）

- 超大判断句或数字，做第一视觉中心
- 必须比人物脸更先抓眼
- 每行不超过 `8` 个字
- 如果塞不进两行，砍字，不要缩字号
- 标题从成稿中带入，不在封面步骤重新想

不要有背景说明小字。封面只靠标题和人物两个元素拦停。

### 2. 人物区（漫画化，看得出是谁）

- 可辨识真人脸（看得出是 Ohtani / Clark / Tatum）
- **但渲染语言是漫画 / 卷封 / 名场面，不是 photoreal 照片，也不是萌系动漫脸**
- 参考体感：灌篮高手脸 + 鬼灭打光 + 名场面定格
- 半身或大腿中段以上
- 不要 tiny figure
- 不要纯抽象概念图
- 默认走 `references/cover-style-pool.md` 里的 `canonical-breakout`，按题型可切换

### 3. 场景背景（漫画化）

- **漫画分镜 / 卷封符号 / 速度线 / 能量线 / 大色块作为主体**
- 球馆 / 看台 / 屏幕**作为符号**保留，但走漫画化（不是真实摄影）
- 至少保留 `2-3` 个场景符号
- 不要背景脏，也不要背景空到不像体育题
- 禁词：`photorealistic` / `studio photo` / `cinematic photoreal` / `8k photoreal`

### 封面字体

- 统一使用 `阿里巴巴普惠体 Bold/Heavy`
- 全帖封面只用这一个字体家族，靠字重区分层级
- 不用宋体、手写体、书法体、圆体
- 深色背景 → 白字或亮色字
- 亮色背景 → 深色字 + 投影或描边
- 标题和背景色不能接近，必须一眼可读

## 三、什么时候套这套封面最稳

- 人物带动商业变化
- 收入、薪资、估值、代言、版权
- “某个人改写了什么”的题

## 三点一、不走预设封面

触发条件（任一成立）：
- 没有明确人物主角（纯规则题、纯数据题）
- 题目本质靠证据截图成立（转播画面、官方公告）
- 用户明确说不要人物封面

不走预设时，封面结构需要重新探索。可参考方向：

- **方向 A：标志性物件 + 大数字** — 规则变化、联盟扩张、金额对比
- **方向 B：场馆/屏幕 + 判断句** — 转播权、平台战争、现场事件
- **方向 C：数据海报（极简排版）** — 纯排名、时间轴、多方对比

这些方向不是固定模板，需要根据具体题目探索。字体和对比规则不变。

不走预设时，应启用 `xhs-cover-template` skill 单独讨论封面结构。

## 四、当前账号默认完整介绍风格

目标不是“介绍得全”，而是“让人快速懂”。

默认写成 `3` 段：

### 第 1 段：先给总判断

- 先说这事到底说明了什么
- 顺手回答：
  - 这是什么
  - 为什么现在热

### 第 2 段：只补必要背景

- 只解释理解这件事必须知道的那一层
- 不写成长人物百科
- 不要从出生讲到现在

### 第 3 段：落到冲突和尾钩

- 为什么值得关心
- 大家在吵什么
- 你怎么看
- 留一个还没讲完的尾钩

## 五、快速判断清单

发之前只看这 6 句：

1. 图 1 是不是生图封面
2. 首图有没有可辨识人脸（如果走预设）
3. 首图标题是否两行以内、和背景有明确对比
4. 首图背景能不能看出这是什么项目
5. 正文第 1 段有没有先给总判断
6. 正文是不是 `3 段内` 就能让小白跟上

## 六、这份说明如何影响 skills

这份说明不定义完整流程。

完整生产流程以仓库根目录 `README.md` 为准。

这份说明只给 skills 提供当前账号的默认假设：

- `xhs-note-assembly`
  默认按这里的 `3 段` 介绍结构写正文，并默认从成稿提取封面信息。
- `xhs-visual-asset-mix`
  默认把图 `1` 当成生图封面，把真人图 / 官方截图优先放到后续页。
- `xhs-cover-template`
  只有当帖子不适合这里的默认人物封面结构时，才单独启用。
- `xhs-image-style-duo`
  接到首图 brief 时，应默认继承这里的标题安全区、人物主角、场景背景和字体限制。

也就是说：

- 这里定义的是 `账号默认`
- 不是 `完整 workflow`
