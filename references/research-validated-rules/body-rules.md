# Body Content — 经验证规则

来源：`xhs_autoresearch/body_autoresearch_summary.md`
实验规模：5 话题 × 25 轮 = 125 次 A/B + Pistons v1/v2/v3 共 30 轮
验证日期：2026-04-06

> 这份规则是从 100+ 次 A/B 跑出来的，每条都给了原始胜率。改这里的规则前请先回看实验数据，不要凭感觉推翻。

## ⭐ S-tier 规则（多话题 / 多轮验证）

### 1. 模块数固定 3，不是 4
- 验证：Clark 5 次接受 / F1 3:3 全胜 / Pistons B wins 5
- 标准 3 模块顺序：**①发生了什么（场景钩子）→ ②谁在赚钱 / 商业逻辑 → ③判断 / 反转收口**
- 4 模块容易变报告，3 模块更像故事
- 不要写 5 模块，不要写 2 模块

### 2. Mystery Arc（埋谜题再揭答案）是骨架
- 验证：Clark accepted / F1 1:1 / Pistons 再次确认
- 先埋一个「读者想知道答案」的问题，再后面给出意外答案
- ❌ 倒金字塔（先给答案）F1 0:1，读者失去阅读动机
- 写正文前先想：这篇的「未揭晓的钩子」是什么？

### 3. Scene Scripting（让读者看见画面）必须服务骨架
- 验证：F1 6:6 完美局 / Messi accepted（作为 mystery 支撑时）
- ❌ Pistons 全模块 scene scripting 失败 A:3 B:1（稀释商业密度）
- **规则**：scene_scripting 是工具，mystery_arc 是骨架。骨架决定场景细节用在哪
- 每个模块至少一句「能让读者看见的细节」（地点 / 动作 / 人物 / 具体数字）
- ❌ 信息陈述：「停办五年后，F1 中国大奖赛回归上海」
- ✅ 场景版：「上海国际赛车场，56 个弯道的柏油路上长了杂草。五年没用了。然后有一天，三台推土机开进来…」

### 4. 数字不可移除
- 验证：F1 0:2 / Pistons A:2 B:0 / 与标题规则一致
- 每个模块必须有一个读者可记住并转述的具体数字
- 去掉数字 → 失去可信度和传播力

### 5. 收口优先级
- 验证：跨 3 话题 + Pistons v2/v3
- **优先级**：A/B/C 押注收口 > 反转 > 二选一判断 > 三选一/预测/站队 ❌
- **A/B/C 押注收口**（v2 验证 B:4 A:1）：选项 C 设计法 — 最后一个选项呼应标题关键词，形成首尾闭环
- **反转式收口**（Messi 5:5 / Pistons B wins 4）：体质需求 — 必须有一个被隐藏的数据点，能改变整题的结论框架
- **二选一**：稳定但温和（扣 1 / 扣 2）
- **预测 / 三选一 / 站队**：商业知识题 0:3 / 0:2 / 0:1 全败

### 6. 字数下限 150-300 字
- 验证：Pistons 缩字数 100-150 全败 A:6 B:0（全场最差）
- 字数不是问题，密度是问题。不要为了短而短

## 🟢 A-tier 规则（单话题强验证 + Pistons v3 复现）

### 7. 第二人称「你是 GM」开场 / 收口
- 验证：Pistons v2 B:3 A:2 / v3 持续验证
- 读者代入决策者视角，评论分叉诱因强
- 例：「你会在哪一步放弃 Cade？」比「活塞管理层的决策」更逼出留言

### 8. 修辞性反问开场（数字型问题）
- 验证：Pistons v2 B:4 A:1 / v3 B:3 A:0
- 数字型问题制造知识缺口
- 例：「你知道这支球队 5 年前年薪是 NBA 倒数第几吗？」

### 9. Mid Plot Twist（模块 2 隐藏数据）
- 验证：Pistons v2 B:4 A:2 / v3 B:2 A:2
- 在模块 2 揭一个颠覆框架的数据
- ⚠️ 注意：plot_twist + 💸 模块语义会重叠（都谈钱）。在 📈 用 plot_twist 时，强调「数量对比」（速度 / 策略），不强调「金额」

### 10. 具体引言替代泛化群体描述
- 验证：Pistons v3 cade_compressed B:4 A:0（v3 最强单突变）
- ❌ 泛化：「粉丝讨论区天天吵要不要放弃他」
- ✅ 具体：「球迷讨论区里最高票的那条评论是『这球队根本选错人了』」
- 用一个真实感的引言或行动细节，替代泛化群体描述

### 11. Hate-bait 反讽弧线
- 验证：Pistons v2 B:4 A:2 / v3 B:4 A:0（与 cade_compressed 并列最强）
- 例：「管理层被骂 → 赢了 → 球迷翻脸」诺刺弧线
- 适合争议商业题，不适合致敬题

### 12. Emoji 是叙事工具，不是装饰
- 验证：Pistons v2 移除 emoji A:4 B:0 / 数字型 emoji ①②③ A:4 B:0
- 🔍 📈 💸 分别对应「谜面 / 揭答 / 金钱逻辑」，本身在做叙事工作
- 规则：用图像 emoji，选择和段落语义匹配的图示
- ❌ 用 ①②③ 这种无语义的 emoji

## ⚠️ 条件性规则

### 13. 反转收口（5:5 vs 0:1 双面例子）
- Messi 5:5 accepted / F1 0:1 rejected
- **必要条件**：必须有一个被隐藏的数据点能改变结论框架
- 故事已完整 → 反转是惊喜
- 故事没新信息 → 反转是空洞

### 14. 类比换算（非球迷版）
- Pistons v2 A:2 B:2 — 看受众
- 非球迷受众优先用，球迷受众保留原版

### 15. Compound 突变可以叠加，但每个 mutation 必须严格在各自模块边界内
- v2 失败案例：3 mutation 内容混进同一模块 → 失去模块化结构
- v3 通过条件：每个突变只触碰指定模块，其他模块 verbatim 保留
- **核心教训：模块化结构是最高优先级，所有 mutation 都不能破坏它**

## ❌ 持续失败 mutation（不要再试）

| Mutation | 验证 | 失败原因 |
|---|---|---|
| 缩字数 < 150 | Pistons A:6 B:0 | 字数不是问题，密度是问题 |
| 移除数字 | F1 0:2 | 失去可信度 |
| 倒金字塔（先给答案）| F1 0:1 | 失去阅读动机 |
| 三选一收口 | F1 0:3 | 强制选项太人工 |
| 预测式收口 | F1 0:2 | 张力不足 / 伤信誉 |
| 站队收口 | F1 0:1 | 商业题效果差 |
| 移除 emoji | Pistons A:4 B:0 | emoji 是功能性锚点 |
| 数字 emoji ①②③ | Pistons A:4 B:0 | 无语义 |
| Contrast 开场（轻度球迷题）| Pistons A:2 B:2 | 球迷覆盖不足 |
| In media res 开场（商业题）| Pistons A:2 B:2 | 竞技腔 vs 商业腔摩擦 |

## 最佳正文公式（整合版）

```
【钩子 — 场景式 or rhetorical question 开场，1-2 句】
让读者看见一个画面 or 一个数字反差

🔍 模块 1 — 发生了什么 + 1 个数字
场景继续，带出新闻事件，解释背景
（可选：第二人称「你是 X」代入）

📈 模块 2 — 商业逻辑 + 1 个数字
"真正的账是这样算的" — 钱、结构、权力
（可选：mid plot twist 揭隐藏数据）

💸 模块 3（收口）— A/B/C 押注 or 反转 or 判断
- 有隐藏数据点 → 反转式（揭示被忽略的关键）
- 一般情况 → A/B/C 押注（选项 C 呼应标题）
- 兜底 → 二选一判断（值/不值）
```
