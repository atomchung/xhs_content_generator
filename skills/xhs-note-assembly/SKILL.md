# XHS Note Assembly

这个 skill 是从切角到可发稿的**主装配器**。

它负责：
- 内部完成事实整理（不需要用户先跑 fact-pack）
- 输出标题、正文、图组任务
- 从成稿中提取封面结构

前提：
- 角度已经基本确定

如果角度没锁，先回到 `xhs-topic-angle-shortlist`。

## 什么时候用

- 用户说“现在写成稿”
- 用户要标题、正文、图上文案一起出
- 用户要 3-4 张图的故事板
- 用户要把前面讨论整理成最终笔记

## 内部事实整理

成稿前，先在内部完成事实整理（不需要用户单独跑 `xhs-fact-pack`）：

- 搜集支撑这个角度的关键事实和数字
- 只在以下情况做完整论证链：商业题、争议题、数字密集题、事实口径风险高的题
- 普通人物介绍或轻知识帖，只需要 `3-5 条必须事实`
- 成稿底部附上事实包摘要，供用户核对数字和来源
- 如果资料不足，在成稿中标出"此处待确认"，不要卡住

## 如果材料还不完整

- 如果角度已锁、但研究资料不足：
  先产出 `标题候选 + 正文骨架 + 缺失信息清单`，不要假装已经能写最终版
- 如果用户只想先看文字方向：
  可以先省略 prompt 和素材说明

## 通用写作约束

### 1. 少用不必要英文，默认输出简体中文

- 标题、正文、图上文案、话题标签默认都用简体中文
- 如果用户给的是繁体草稿，最终成稿默认转成简体中文，引用原话或专有名词除外
- 只有在专有名词确实必要时才保留英文，并且第一次出现要给中文解释
- 不要为了“像体育媒体”保留一串英文术语，读者看不懂就会直接划走

### 2. 先给总判断，再把故事讲明白

- 默认读者不懂这项赛事、规则或商业背景
- 开头第一句优先给一个总判断，先回答“这事到底说明了什么”
- 开头前两段必须回答：`这是什么`、`为什么现在热`、`为什么你该关心`
- 解释顺序优先是：事件 -> 冲突 -> 背后的钱/规则 -> 你的判断

### 3. 语气像朋友解释，emoji 适度使用

- 语气要像“懂体育的朋友在解释”，不要像行业报告
- 标题允许 `0-2` 个 emoji，正文每段最多 `1` 个 emoji
- emoji 只能帮忙提气氛、分段或强调，不要代替信息本身
- 优先用和运动、情绪、涨跌、对比相关的 emoji，不要堆满

## 组装原则

### 1. 正文结构要短，但论点链不能断

默认写成 `2-3` 个完整小段；只有复杂题才放宽到 `4` 段。

推荐段落动作：
- 每段只讲一件事，不要一段里塞完背景、数字、观点和结论
- 每段前半句优先出现一个数字、变化或明确事实
- 可以用很短的小标签起段，例如：`先说结论`、`为什么现在`、`但问题还没完`
- 最后一段要留一个“事情还没讲完”的尾钩，不要平着收掉

推荐 3 到 4 个问题块：
- 这到底是什么
- 发生了什么
- 为什么这样做
- 为什么大家在吵
- 现在看值不值 / 该怎么判断

### 1.1 固定讲故事动作

产文时，默认先检查这 4 个动作有没有做到：
- 开头加一句总判断
- 正文改成 `2-3` 个小段 + 小标签
- 每段前半句尽量先给数字、变化或反直觉事实
- 最后一段留一个“但问题还没完”的尾钩

### 1.2 当前账号默认完整介绍风格

如果是“人物带动变化”的介绍型帖子，默认写成这个顺序：

- 第 1 段：
  先给总判断，再说 `这是什么 + 为什么现在`
- 第 2 段：
  只补足够理解这件事的背景，不写成长人物百科
- 第 3 段：
  落到 `为什么值得关心 / 大家在吵什么 / 你怎么看`

要点：

- 介绍人物，不等于写人物简历
- 默认先写“这个人改写了什么”
- 让不懂的人 3 段内跟上，比写全更重要

### 2. 标题先抢打开率

标题优先顺序：
- 争议
- 问题
- 人名 / 赛事
- 数字

### 3. 图文分工要互补

- 图上讲最直观的东西
- 正文讲“为什么”
- 来源沉到底部

同时要满足：
- 首图和首段让不懂的人也知道主题大概是什么
- 图上文案不要堆英文缩写

### 4. 保留互动收口

收口不要问太空泛的问题。

优先用：
- 三选一
- 会 / 不会
- 值 / 不值
- 你站哪边

### 5. 人工最终拍板

默认由人类决定：
- 最终标题
- 封面方案
- 删掉哪些过重的解释

### 6. 话题标签要能搜到，不要只是凑数

- 默认输出 `4-8` 个话题标签
- 前 `2-3` 个标签优先绑定核心人物、赛事或联盟
- 其余标签再补项目大类、情绪入口或话题场景
- 以简体中文标签为主，只有平台常用英文标签才保留英文
- 不要堆太泛的空标签，也不要用和正文无关的流量词

## 图组预设

默认不需要单独跑 `xhs-visual-asset-mix`，直接套用账号预设：

- 图 1：生图封面
- 图 2-4：真人照片或官方截图为主

只有在用户明确纠结"真人图还是生图"时，才单独启用 `xhs-visual-asset-mix`。

## 封面提取

封面从成稿中自动提取，不需要单独跑 `xhs-cover-template`。

### 提取规则

1. **标题**：直接使用成稿锁定的最终标题
   - 检查是否符合两行限制（每行不超过 8 字）
   - 如果超过，在这步砍字
2. **主角**：从正文中识别绝对主角（通常是第一段提到的核心人物）
3. **场景**：从正文背景信息中提取场景符号

### 封面结构（账号预设）

三层，从上到下：

1. 标题区：超大判断句或数字，最多两行，第一视觉中心
2. 人物区：可辨识人脸，半身构图
3. 场景背景：深色场景底，体育现场符号

不加背景说明小字。封面只靠标题和人物拦停。

### 封面字体

- 统一使用 `阿里巴巴普惠体 Bold/Heavy`
- 靠字重区分层级，不混用其他字体
- 深色背景用白字或亮色字，标题和背景必须有明确对比

### 什么时候需要单独启用 cover-template

- 这篇没有人物主角，需要探索替代封面方向
- 用户明确说要换封面结构
- 预设结构明显不适合这个题

## 存档约定

如果当前已经有贴文目录，默认把成稿存到：

- `demo_posts/<date>-<slug>/text/post.md`

标题候选、最终标题、正文、图组和来源都应该写进这个文件，而不是只停在聊天里。

## 不要这样做

- 不要重新发明角度
- 不要把 fact pack 原封不动贴进正文
- 不要一边写成稿一边重新定义每张图的任务
- 不要把所有信息都塞进标题和封面
- 不要默认读者已经懂这项赛事或规则
- 不要用英文和黑话制造”懂的人自然懂”
- 不要在封面步骤重新想标题，标题从成稿带入
- 不要每篇都单独跑 visual-asset-mix，套用图组预设即可
