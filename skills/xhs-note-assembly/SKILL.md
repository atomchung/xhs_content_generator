# XHS Note Assembly

这个 skill 负责把前面已经锁好的内容组装成一篇可发的小红书帖子。

前提：
- 角度已经基本确定
- fact pack 已经有了
- 图片分工已经清楚

如果前提不成立，先回到前面的 skill，不要硬写。

## 什么时候用

- 用户说“现在写成稿”
- 用户要标题、正文、图上文案一起出
- 用户要 3-4 张图的故事板
- 用户要把前面讨论整理成最终笔记

## 通用写作约束

### 1. 少用不必要英文，默认输出简体中文

- 标题、正文、图上文案、话题标签默认都用简体中文
- 如果用户给的是繁体草稿，最终成稿默认转成简体中文，引用原话或专有名词除外
- 只有在专有名词确实必要时才保留英文，并且第一次出现要给中文解释
- 不要为了“像体育媒体”保留一串英文术语，读者看不懂就会直接划走

### 2. 先给总判断，再把故事讲明白

- 默认读者不懂这项赛事、规则或商业背景
- 开头第一句优先给一个总判断，先回答“这事到底说明了什么”
- 开头前两段必须回答：`这是什么`、`为什么现在热`、`为什么你该关心`
- 解释顺序优先是：事件 -> 冲突 -> 背后的钱/规则 -> 你的判断

### 3. 语气像朋友解释，emoji 适度使用

- 语气要像“懂体育的朋友在解释”，不要像行业报告
- 标题允许 `0-2` 个 emoji，正文每段最多 `1` 个 emoji
- emoji 只能帮忙提气氛、分段或强调，不要代替信息本身
- 优先用和运动、情绪、涨跌、对比相关的 emoji，不要堆满

## 组装原则

### 1. 正文结构要短，但论点链不能断

默认写成 `2-3` 个完整小段；只有复杂题才放宽到 `4` 段。

推荐段落动作：
- 每段只讲一件事，不要一段里塞完背景、数字、观点和结论
- 每段前半句优先出现一个数字、变化或明确事实
- 可以用很短的小标签起段，例如：`先说结论`、`为什么现在`、`但问题还没完`
- 最后一段要留一个“事情还没讲完”的尾钩，不要平着收掉

推荐 3 到 4 个问题块：
- 这到底是什么
- 发生了什么
- 为什么这样做
- 为什么大家在吵
- 现在看值不值 / 该怎么判断

### 1.1 固定讲故事动作

产文时，默认先检查这 4 个动作有没有做到：
- 开头加一句总判断
- 正文改成 `2-3` 个小段 + 小标签
- 每段前半句尽量先给数字、变化或反直觉事实
- 最后一段留一个“但问题还没完”的尾钩

### 2. 标题先抢打开率

标题优先顺序：
- 争议
- 问题
- 人名 / 赛事
- 数字

### 3. 图文分工要互补

- 图上讲最直观的东西
- 正文讲“为什么”
- 来源沉到底部

同时要满足：
- 首图和首段让不懂的人也知道主题大概是什么
- 图上文案不要堆英文缩写

### 4. 保留互动收口

收口不要问太空泛的问题。

优先用：
- 三选一
- 会 / 不会
- 值 / 不值
- 你站哪边

### 5. 人工最终拍板

默认由人类决定：
- 最终标题
- 封面方案
- 删掉哪些过重的解释

### 6. 话题标签要能搜到，不要只是凑数

- 默认输出 `4-8` 个话题标签
- 前 `2-3` 个标签优先绑定核心人物、赛事或联盟
- 其余标签再补项目大类、情绪入口或话题场景
- 以简体中文标签为主，只有平台常用英文标签才保留英文
- 不要堆太泛的空标签，也不要用和正文无关的流量词

## 存档约定

如果当前已经有贴文目录，默认把成稿存到：

- `demo_posts/<date>-<slug>/text/post.md`

标题候选、最终标题、正文、图组和来源都应该写进这个文件，而不是只停在聊天里。

## 输出格式

```markdown
## 标题候选
1. ...
2. ...
3. ...

## 最终标题
- ...

## 正文
### 小标签 1
...

### 小标签 2
...

### 小标签 3
...

## 图组
### 图 1
- 任务：
- 图上文案：
- 画面说明：
- prompt / 素材说明：

### 图 2
...

## 参考来源
- ...

## 话题标签
- #...
- #...

## 需要人拍板
- 标题：
- 封面：
- 删减：
```

## 不要这样做

- 不要重新发明角度
- 不要把 fact pack 原封不动贴进正文
- 不要一边写成稿一边重新定义每张图的任务
- 不要把所有信息都塞进标题和封面
- 不要默认读者已经懂这项赛事或规则
- 不要用英文和黑话制造“懂的人自然懂”
