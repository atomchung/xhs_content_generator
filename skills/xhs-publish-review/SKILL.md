# XHS Publish Review

这个 skill 只做发布后复盘。

目标不是夸哪版更好，而是回答：
- 最后为什么会改成这样
- 哪些改动提升了帖子
- 哪些风险是被埋进去的
- 下次工作流该怎么拆

## 什么时候用

- 用户给了真实发文链接
- 用户要对比草稿和发布版
- 用户要总结这轮循环
- 用户要把经验写回 skill

## 工作流

### 1. 先对齐两份东西

- 草稿版本
- 真实发布版本

如果有图片，也要看图，不只看文案。

### 2. 差异分三类

- 文案差异
- 图片差异
- 流程差异

### 3. 每个差异都必须做归因

不要只写“发布版更短”。

要写：
- 为什么会变短
- 这对小红书有效在哪里
- 换来了什么
- 牺牲了什么

### 4. 必须落回工作流

复盘最后一定要变成：
- 哪一步应该提前
- 哪一步必须让人介入
- 哪一步适合拆成独立 skill

## 输出格式

```markdown
## 差异清单
### 文案
- 差异：
- 归因：
- 下次规则：

### 图片
- 差异：
- 归因：
- 下次规则：

### 流程
- 差异：
- 归因：
- 下次规则：

## 新的工作流
1. ...
2. ...
3. ...

## 必须人工介入的点
- ...
```

## 不要这样做

- 不要只说“整体更好”
- 不要只复盘正文，不看图片
- 不要把问题归咎成“模型不行”
- 不要复盘完却不改工作流
