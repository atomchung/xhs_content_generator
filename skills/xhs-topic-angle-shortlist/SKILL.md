# XHS Topic Angle Shortlist

这个 skill 只负责一件事：

帮当前账号找到 `下一批值得研究的题目和可能切角`。

它负责的是：

- 发想题目
- 给每个题目找 `1-3` 个可能切角
- 选出这次最值得继续研究的题
- 把没选中的点子放回 backlog

它不负责锁最终故事线。

最终切角是在 `fact_pack` 之后，通过 `story_spine` 确认的。

不要在这一步直接写完整正文，也不要先做图片 prompt。

## 什么时候用

- 用户还没有明确题目
- 用户只有一个大方向，但还没收窄到一篇帖子
- 用户已经有题目，但还缺 `2-3` 个研究方向或可能切角
- 用户要维护或回看题目 backlog
- 用户说“先想几个角度”
- 用户说“哪个更值得先研究”
- 用户只要标题方向或故事入口
- 用户说“先别写正文”

## 什么时候不要用

- 已经选定了一个题，并且正在做单篇研究，直接进入 `xhs-fact-pack`
- 已经有完整研究，只差把研究收成故事，进入 `research/story_spine.md`
- 最终故事线已经锁了，直接进入 `xhs-note-assembly`
- 用户要长期系列规划、内容支柱、视觉系统、工作流沉淀
  这类内容优先放进 `explorations/`
- 用户明确说“先不要落成具体帖子”

## 两种模式

### 模式 A：用户没有题目

输出 `2-3` 个值得继续研究的题目 / 可能切角候选，并给一个明确推荐。

### 模式 B：用户已有题目，但没切角

围绕同一个题目，输出 `2-3` 个可研究的切角方向，并给一个明确推荐。

默认优先走这个模式，不要把“已有题目”又扩成一场新的大 shortlist。

## 如果实时信息不完整

- 如果账号页面打不开：
  明确说明，然后退回到本地保存的账号 DNA、过往 review 或用户给的截图
- 如果当前热点搜不到足够强的候选：
  先分成 `已验证当前热点` 和 `可做的常青候选`，不要把旧题伪装成“今天最热”
- 如果用户只给了一个很模糊的方向：
  先收窄成更具体的母题，再给 `2-3` 个切角

## 输出目标

默认输出：

- `2-3` 个值得继续研究的候选
- `1` 个本轮优先研究项
- 每个角度都要有一句 `why now`

每个候选默认说明这些信息：

- 一句话题目
- 可研究的切角方向
- 为什么现在值得做
- 为什么适合这个账号
- 小白入口
- 研究时最该先确认什么
- 为什么中国小红书用户会点
- 可用的互动收口
- 角度延展性（AutoResearch 发现：商业/叙事角度多的话题接受率更高，如 Masters 60%；纯表现型话题如 Jokic 只有 10%，收敛太快没有改写空间）

默认不要展示：

- 打分表
- 综合分
- `5` 个以上大候选池
- 每题 `3` 个以上切角的大评审表

如果你内部需要筛子和评分，可以内部使用，但不默认把整套评估过程暴露给用户。

## 通用写作约束

### 1. 少用不必要英文，默认按简中读者理解来写

- 题目、切角、解释话术优先用中文
- 必须提英文术语时，第一次出现先给中文解释
- 如果一个角度离开英文缩写就讲不清，说明这个角度还没翻译成人话，要先重写

### 2. 先给小白入口，再给硬核信息

- 默认读者不懂联赛简称、规则缩写和历史背景
- 每个候选至少要能用一句话说清：
  `这是什么 + 为什么现在热 + 为什么值得点`
- 切角不是给硬核球迷打暗号，而是要让路人也能顺着点进去

## 工作流

### 0. 先判断现在是哪种模式

- 如果用户没题目：走 `模式 A`
- 如果用户有题目但没切角：走 `模式 B`
- 如果已经进入单篇研究：不要继续 shortlist，直接转 `xhs-fact-pack`

### 1. 先复看 backlog 和账号最近发过的内容

在给任何候选前，必须先看用户提供的小红书账号或最近笔记。

- 如果 `explorations/backlog/topic-angle-backlog.md` 已存在，先复看 backlog
- 优先看最近 `10-20` 条公开可见内容
- 记录：高频人物、联赛、商业题、历史题、女子体育题、标题句法
- 如果页面打不开，要明确说明，然后退回本地资料
- 不要跳过这一步，除非用户明确说“不要参考账号历史”

### 2. 再核对当前热点

至少覆盖两类来源：

- 体育热点：联盟 / 赛事 / 球员 / 官方赛程 / 主流体育媒体
- 体育商业：版权 / 估值 / 赞助 / 转播 / 平台竞争 / 女子体育商业化

优先搜索：

- 官方或一级来源
- AP / ESPN / NCAA / MLB / NBA / WNBA / NFL / F1 / IOC
- Front Office Sports / Sportico / Boardroom

如果用户提到“最近 / 最新 / 今天 / 现在”，必须写绝对日期。

### 3. 先找“能讲成一篇”的角度，不做大题海

优先选下面这几类：

- 大事件背后的钱、规则、平台、权力
- 一个明星带出的更大行业变化
- 一件争议为什么会引发站队
- 一个赛果背后真正重要的结构变化

默认收敛到 `2-3` 个候选，不要扩成 `5+` 个大池子。

### 4. 切角必须是“问题句”或“判断句”

不要给这种：

- `WBC 转播权变化`
- `大谷与 Netflix`

要给这种：

- `网飞为什么愿意为日本 WBC 砸这么多钱？`
- `这不是转播权新闻，而是日本视频入口大战`
- `如果没有大谷，网飞还会不会赌这笔钱？`

同时要满足：

- 不懂这个赛事的人，也能从句子里知道它大概在讲什么
- 不靠英文缩写堆神秘感

### 5. 默认只保留一次拍板

这一步机器只负责缩小范围，不负责替人做最终决定。

默认只要求人类拍板一件事：

- 选这次先研究哪个题 / 哪个研究方向

不要把拍板拆成多轮：

- 选哪个题目
- 选哪个最后切角
- 偏争议还是偏人物
- 要不要做成长帖

这些可以合并成一次最终选择。

### 6. 一旦决定继续，先更新 backlog，再进入 post workspace

如果用户决定继续做某个题，先把 backlog 里的候选更新为：

- `active now`
- `parked`
- `watch later`

默认 backlog 放在：

- `explorations/backlog/topic-angle-backlog.md`

然后再把后续资产放进同一个贴文目录：

- `demo_posts/<date>-<slug>/research/`
- `demo_posts/<date>-<slug>/text/post.md`
- `demo_posts/<date>-<slug>/prompts/`
- `demo_posts/<date>-<slug>/images/`

如果目录还不存在，优先创建它，再继续后面的 skill。

### 7. 明确区分“探索”和“发想”

这里的“发想”是指：

- 已经围绕某一个事件、人物或问题
- 正在决定这一篇要怎么切
- 很可能会进入正文、图组和发布

这种情况应该进入：

- `demo_posts/<date>-<slug>/`

这里的“探索”是指：

- 还在想一个系列值不值得做
- 还在比较多种视觉语言或封面模板
- 还在整理参考作者和账号方向
- 这一轮产出会影响很多后续帖子，而不是只影响一篇

这种情况应该进入：

- `explorations/series/`
- `explorations/backlog/`
- `explorations/visuals/`
- `explorations/workflows/`

## 不要这样做

- 不要默认给 `5` 个以上题目
- 不要默认给每题 `3` 个以上切角
- 不要把完整评分表直接展示给用户
- 不要在没复看账号和没搜当前热点前就开始列题
- 不要把“先研究哪个题”误当成“最终切角已经锁了”
- 不要先写长正文
- 不要在没锁角度前开始打磨封面
- 不要把“热”误当成“适合做小红书”
