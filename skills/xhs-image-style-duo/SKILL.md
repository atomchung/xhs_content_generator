# XHS Image Style Duo

这个 skill 只做两条风格线：

1. 动漫名场面封面风
2. Q 版棒球吉祥物风

目标不是一次把所有东西都画满，而是先锁住“人物和动作”，再去换背景和装饰。这样背景频繁调整时，不需要每次从零重生。

这个 skill 不负责决定整篇帖子该用真人图、官方截图还是生图。那一步交给 `xhs-visual-asset-mix`。这里只负责已经确定要生图的页面。

## 什么时候用

遇到这些任务直接使用：

- 用户要把一个故事做成两种图片风格
- 用户说“只要动漫和 Q 版”
- 用户说“背景太乱”“动作没张力”“不像封面图”
- 用户要更像动漫名场面 / 卷封 / 海报构图
- 用户要 Q 版更像 `実況野球` 或你给的那种小红薯感
- 用户想优化图片生成顺序，避免背景一改就全部重跑

## 先做 4 个判断

1. 主角是谁
必须只有一个绝对主角。

2. 这一张图最该卖什么
默认从这四个里面选一个：
- 脸
- 动作
- 冲突
- 情绪

3. 背景是不是稳定的
如果用户明显还在探索背景，先不要把背景写死。

4. 这是首图还是辅助图
首图更重人物和动作，辅助图才允许背景信息多一点。

## 更好的生成顺序

不要一开始就写“完整终稿 prompt”。按这个顺序做：

### Step 1. 抽故事骨架

先拆成 4 个元素：

- 主角
- 动作瞬间
- 冲突/情绪
- 背景符号

其中前 3 个先锁死，背景符号暂时只记关键词。

### Step 2. 先做人物锚点

先写 `subject anchor prompt`：

- 只画主角
- 只保留很简单的背景
- 重点锁脸、发型、服装、姿势、镜头

这一层的目的：

- 锁住“这个人长什么样”
- 锁住“他在这个故事里最有张力的动作”

### Step 3. 再做背景层

单独写 `background prompt`：

- 不抢主角
- 只承担世界观和冲突说明
- 用 2-3 个背景符号就够

如果背景之后要改，优先只改这层。

### Step 4. 最后合成封面 prompt

把人物锚点和背景层合成成 `final cover prompt`。

如果背景经常变，优先重写：

- `background prompt`
- `final cover prompt`

不要先推翻 `subject anchor prompt`。

## 两条固定风格线

### A. 动漫名场面封面风

用户说“动漫风格”时，不是泛二次元，而是：

- 动漫名场面转化
- 动漫卷封 / 海报主视觉
- 经典对峙或挥棒瞬间的封面化

要点：

- 动作必须有瞬间爆发力
- 构图更像封面，不像信息海报
- 背景必须干净，最多保留 2-3 个符号
- 借“名场面”的视觉结构，不复制具体 IP 角色

优先使用这些构图原型：

- 低机位英雄站姿
- 挥棒前蓄力定格
- 对峙式左右冲突
- 风和能量线集中指向主角

必须避免：

- 背景满屏细节
- 旧纸污渍太重
- 动作像站桩摆拍
- 现代萌系脸导致不像热血体育番

### B. Q 版棒球吉祥物风

Q 版默认往这条线靠：

- `実況野球` 式棒球吉祥物感
- 你给的那种豆薯 / 小红薯运动角色感
- 可爱但仍然能表达 prompt 里的故事元素

要点：

- 圆豆身形
- 短手短脚
- 厚描边
- 小黑眼或很简洁的五官
- 纯净底色或面板式构图

额外要求：

- 必须把 prompt 里的次要元素翻译成 2-3 个可爱元素
- 例如棒球题可以变成：球棒、帽子、记分牌、火焰/冰能量、城市小图标
- 不要只是把真人缩成大头娃娃

必须避免：

- 过度复杂背景
- 乱七八糟的道具
- 过度精细的二次元渲染
- 廉价贴纸感

## 如果要直接生成图片

优先用脚本：

- [scripts/generate_style_duo.py](./scripts/generate_style_duo.py)

这个脚本现在和 skill 名称一致，只输出两条风格线，并且会额外输出：

- `story_atoms`
- `subject_anchor_prompt`
- `background_prompt`
- `final_prompt`

用途：

- 先稳定角色和动作
- 再单独试背景
- 最后输出最终封面图

## 不要这样做

- 不要再输出第三种真人风
- 不要先把背景写得比主角还重要
- 不要用“动漫风”这三个字糊过去
- 不要让 Q 版只是大头版真人
- 不要在背景还没定时就反复重做角色
